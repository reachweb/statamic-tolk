# Changelog

All notable changes to Tolk are documented in this file.

## Unreleased

### Added

- **Settings** in the **Tools › Translations** menu, below **Audit**, for users who may edit Tolk's settings.
- **Translated slugs**, a setting that lists the collections whose new localizations get a slug made from their translated title, the way Statamic makes slugs in the target site's language. It is empty by default, so new localizations keep their origin's slug as before, and an existing slug is never changed.
- **Automatic updates**, off by default (the settings' new Automation tab): saving a published entry in its origin updates its localizations in the background, as **Update translations** does, and with **Create missing localizations** also translates it into the sites that have none. A new published entry of a collection with **Propagate** on is translated into the localizations Statamic creates for it, also without **Create missing localizations**. They can be limited to some collections, and in collections with revisions published at once. Each update is a run, listed as an automatic update, followed in the origin's banner after the save, and counted under **Automatic updates** in the Overview's usage; the localization's banner says when an automatic update last saved it. With a queue worker for Tolk's runs the update runs on the queue. Without one, a save inside a queue job (an import, say) queues the update on that job's queue, and any other save runs it in the process that saved the entry, after its response, which reaches the browser first only under PHP-FPM, LiteSpeed or FrankenPHP; the Audit page warns on other web servers, where the save waits for the whole update.
- **Reset** on the Overview's usage card, which deletes the month's usage, and on the runs list, which deletes the finished runs; both ask first and are offered to users who may edit Tolk's settings.
- `tolk:baseline --protect`, which does what the editor's **Protect this entry from updates** does for every item of the collections, taxonomies, global sets or navigations it names, so Translate and Update leave their machine translations alone. It is the only way to protect a global set or a navigation, such as one whose pages were added, removed or moved by hand: Update rebuilds an outdated tree from the source's, so the pages removed come back, the pages added go and the source's order returns.
- `LICENSE.md` with the licence terms, which the README and the installation guide link.

### Changed

- Tolk's model catalog is no longer part of `config/tolk.php`, so each update of Tolk brings its new models, prices and request options to every site, including a site that published the config. `models` in the config now only adds models or changes Tolk's, by id: an entry replaces the keys it names and keeps Tolk's others. **If you published the config from 1.0.0-beta.1**, delete the entries under `models`, or keep only the keys you changed: each entry of the copy keeps replacing Tolk's model with the same id, and the copy's Claude Haiku 5.5 sends a thinking option that Anthropic refuses.
- A request from the editor, a browser-driven run or a queue run carries at most 4,000 characters of source text (`batch.max_chars.web`), instead of 6,000. With real providers, 6,000 characters into Greek took Claude Sonnet 5.5 43 seconds against the 45-second `http.timeout.web`, so one slow answer timed out and was sent again in two halves; 4,000 take about 30 seconds. **If you published the config from 1.0.0-beta.1**, it still sends 6,000: set `batch.max_chars.web` to `4000`, or remove the keys you did not change on purpose. Remove a whole top-level key, such as `batch`: Laravel fills in Tolk's defaults only for the top-level keys a published config leaves out, not for a key inside one.
- The editor's translation options are grouped and shorter, so they fit a laptop screen: the model and the reviewer side by side, the reviewer enabled only while it has something to do, the actions that take effect at once under their own heading, and the offer preference as a switch.
- The banner of a localization shows its counts and its buttons on one line, without repeating that it is up to date; the origin's list of translations lines up and colours each status.
- A status has the same colour in the banner, the origin's list and the Overview.
- The editor names models as the model selects do ("Gemini 3.8 Flash" rather than `gemini-3.8-flash`): in the banner's summary, the offer and the reviewer's changes.
- The origin's banner is hidden while every localization is up to date.
- A page skipped because its collection's home page is not translated into the site yet says why (the first page saved into the site's empty tree would become its home page) and links to the home page, in the push results and on the run's page.

### Fixed

- A translation can no longer put attributes on a page through a Markdown field. Statamic's Markdown parser renders a CommonMark attribute list such as `*every day*{x-init="…"}`, so a translation that adds an attribute list or a curly brace is now rejected, and the source's own attribute lists are sent whole, as placeholders the model cannot change. Before, a run saved such output, and the page rendered `x-init`, `x-on:`, `style` or `class` attributes that the source did not have.
- A translation can no longer turn escaped text into markup in a table cell, list item, array value, translation string or form text: one whose tags differ from the source's is rejected, and such texts that hold HTML are sent as HTML. Before, runs, `tolk:lang` and `tolk:forms` saved a `Kids < 12` turned into `<img src=x onerror=…>`, a link turned into a `javascript:` link, or a closing tag dropped.
- In a Markdown field with Antlers on, a tag in a link or image destination or in a reference definition reaches the model whole as a placeholder, and a translation that drops a `}}` of its source is rejected. Before, the tag's parameters went out as text, so a run could save `{{ config:app.key }}` where the source had `{{ link to="contact" }}`, or leave a tag open.
- A Markdown translation that adds a reference definition in a quote or a list item, or one whose label spans two lines, is rejected, and the source's own definitions there reach the model whole as placeholders, as one at the start of a line does. Before, a run saved such a definition, so a reference like `[our story][x]` linked wherever the model chose, a `javascript:` link included, and the model saw the destinations of the source's own and could change them.
- A Markdown translation that adds a code fence is rejected. Before, a run could save a paragraph that ends in an open fence, which the next code sample's fence closed, so that sample's HTML, a `<script>` included, was rendered on the page.
- A translation that puts a `{` right before an Antlers tag is rejected. Before, a run could save `{{{ site:name }}` in a field with Antlers on, and the localized page failed with an Antlers syntax error.
- A Markdown translation that adds or changes a web address in emphasis or after an underscore (`_https://…_`, `x_www.…`) is rejected, as one after a space is. Before, a run saved it, and a Markdown field with automatic links linked it.
- A Markdown translation is read back with the backslashes before its placeholders, so a backslash or backtick that breaks a code span, a link destination moved out of its link or a dropped escape can no longer turn the source's code or escaped text into a script, a `javascript:` link or an attribute. Text shaped like a placeholder behind a backslash (`\<x1/>`) no longer keeps its paragraph in English.
- **If you translated with 1.0.0-beta.1**, the fixes in this release send some texts to the model differently, so their beta.1 translations read "edited by hand" after the upgrade, and Update and automatic updates leave them alone: table cells, list items, array values, translation strings and form texts that hold HTML tags; form texts with a `|`; Markdown blocks with an Antlers tag in a link or image target or a reference definition, with a reference definition in a quote or a list item or with a label over two lines, or with an attribute list that beta.1 left as text (`{x-on:click="…"}`); and Bard code blocks and line breaks stored in the older Bard editor's format. Translate them again, which is advisable anyway, as beta.1 made them without the checks these fixes add: with **Translate from origin** on the field in the Control Panel, or with `tolk:translate --force` for the collection and site (it also replaces the other fields edited by hand that it selects), `tolk:lang --force --group=<file>` (`_json` for the JSON file) and `tolk:forms --force`.
- Missing space between paragraphs in Translate into…, the offer and the push results.
- `tolk:lang` writes a key of a PHP translation file that holds a dot (`'faq.title' => …`) as one key, as the source has it, instead of nesting it. A key that is also the start of another (`'faq'` next to `'faq.title'`) no longer loses its translation, which made `__()` return an array, and is no longer sent again on every run.
- `tolk:lang` tracks keys that read as numbers, such as `'404'` in `lang/en/errors.php` or `"2026"` in `lang/en.json`. Their translations were recorded under the wrong key, so they read "edited by hand" and `--mode=update` never refreshed them. Keys translated by 1.0.0-beta.1 read "edited by hand" until they are translated again with `tolk:lang --force --group=<file>` (`_json` for the JSON file).
- `tolk:lang` copies strings with nothing to translate, such as URLs, email addresses and phone numbers, from the source into the target file, as it copies numbers, so `__('site.url')` no longer shows `site.url` on a translated site (a JSON file has no fallback language). They are copied whenever the command writes the file.
- A text that moves between `lang/{source}.json` and a form, such as a form label added to the JSON file, keeps its record, so `tolk:lang` and `tolk:forms` no longer read its translation as edited by hand.
- `tolk:forms` collects the label of a form field without a `display`, which Statamic makes from the field's handle (`your_message` becomes "Your Message") and shows in the submission email and in validation messages.
- When the provider rejects the key or the model, `tolk:lang` and `tolk:forms` report the file they were translating as failed, count it in the summary and name the files they did not get to, instead of leaving the file's line empty and reporting Failed 0.
- Requests to OpenAI's models from GPT-5.6 on whose id starts with `gpt-` no longer pay for cache writes: by default OpenAI wrote every whole request to its prompt cache, at 1.25 times the input price, and never read it back. A fine-tuned model (`ft:…`) gets the cache option that stops this only from its own `options` in the config. The usage figures also price GPT-6.1 Sol's cache reads at its own rate, 5% of the input price.
- The Overview's usage listed the calls of `tolk:translate` and `tolk:site` under **Runs**; they now count under **Command line**, unless the run is handed to the queue with `--queue`.
- The listing action's **Translate into** no longer offers the site that the selected entries or terms are translated from, which created a run with nothing to translate; a run into only that site is refused with the reason.
- A run's page shows the reviewer's corrections: an item the reviewer corrected says how many, and **View changes** shows each with the text before and after and the reason, as the editor does.
- "1 call" instead of "1 calls" in a run's usage and the Overview's usage of the month, and the count can be pluralised in a host's translation.
- On the page of a stopped run, the error is on a line of its own instead of running into the result ("0 done.The AI provider…").
- On a narrow screen, the tables of the Overview, the runs list and a run's page scroll sideways inside their card, as Statamic's listings do, instead of running off the card and scrolling the whole page.
- The description of the **Translate content** permission no longer says it gives the listing action, which needs **Run bulk translations**; it now names what it gives, as the installation guide does.
- The editor's options review with the reviewer they show when you choose another model. Before, the reviewer marked "(default)" was replaced by the one the settings would pick for that model.
- The editor's options remember both the model and the reviewer when you change both. Before, one of the two choices could be lost.
- The editor says "Reviewed with …" only when the reviewer checked the text. Before, it said so whenever review was on, also when no review ran: nothing needed a model, every review failed, the provider rejected the reviewer, or the translation was cancelled first.
- The editor's options offer **Review** with **Overwrite manual edits** checked on a localization whose fields were all edited by hand, such as one translated before Tolk was installed. Before, Review and the reviewer were only available while the form held machine translations.
- After a failed translation the editor's banner still shows **Options** (and **Review** where it applies), so you can choose another model when the provider rejected one. Before, it offered only **Retry**, which repeated the rejected model.
- A page that a run, Translate into… or the command line creates in a structured or orderable collection is placed at its origin's position among the pages already in the target site's tree, instead of at the end of its level in the order the translations finished. Pages already in the tree keep their order.
- A field saved with exactly the text Tolk produced reads as machine-translated, also when a hand-typed text of the field was saved before it, from a second tab or as an edit that was then undone. It used to stay "edited by hand", so Update skipped it.
- Update keeps the translation of each copy of a text that appears more than once in a field (a repeated paragraph, label or table cell), instead of giving every copy the first copy's translation, which lost a review correction or a translation made in context.
- Translating a field again keeps the ids of the localization's Replicator and Grid rows and Bard sets where the origin's have none (content imported or saved by code), in the editor too, instead of giving every row a new id each time, which rewrote unchanged lines in git.
- A cancelled or aborted run, or a cancelled Translate into…, no longer lists items as "Translating" when they had units left: they go back to waiting, and Resume continues them at once, without repeating what was already translated.
- Cancel with review on no longer drops the translations already on their way: they are still reviewed and filled into the form, instead of the summary saying that no fields were translated.
- A Markdown field emptied in the origin shows empty in the localization after Update or "Translate from origin", instead of keeping its old text on screen until the page is reloaded.
- After Translate, Update or Review the keyboard focus moves to Cancel while the translation runs, instead of resting on a status count whose tooltip covered the page's header.
- The confirmation of "Translate from origin" gives the keyboard focus back to the field's actions menu after Esc or Cancel, and moves it to the banner's progress after Translate, instead of leaving it at the top of the page.
- `tolk:site --dry-run` plans and estimates the content of the collections, taxonomies and global sets it would enable for the site, and lists their fields that are not localizable, as the run does. It used to leave them out, so the dry run of a new site found almost nothing to translate.
- After Ctrl-C or an abort, `tolk:translate` and `tolk:site` count the targets translated but not saved apart from those not translated, and advise resuming the run in the Control Panel within `plan_ttl` (two hours by default) to save them without paying for them again. They no longer advise running the command again when that would translate them anew, or when the cause of an abort would stop it too.
- Ctrl-C at the question of `tolk:translate` and `tolk:site` ("Translate and save them?") deletes the run it prepared, instead of leaving it on the Runs page as not started, where anyone allowed to run bulk translations could start it. The question is now asked with Laravel Prompts.
- `tolk:translate` refuses `--from` when it names the only `--site`, and warns that the navigation of the `--from` site is left out when it is one of several sites, instead of leaving it out without a word.
- The progress bars of `tolk:translate` and `tolk:site` stop where the work stopped after Ctrl-C or an abort, instead of jumping to 100%, and the terminal's progress indicator is reset.
- The dry run of `tolk:translate` says a page whose home page is not translated into the site yet "would be skipped", as the run skips it, instead of "would fail".
- `tolk:status` and the Overview say that `tolk:baseline` records the origin of each field translated by hand, instead of "to record it", which could be read as recording the change.
- `php please tolk:site` no longer stops with a `TypeError` when it hands over to `tolk:translate`, after the questions that change the configuration. `php artisan tolk:site` was not affected.
- The editor keeps what you type right after it fills a field, undoes or saves. A correction typed while it reads a filled field back, about a third of a second after the fill or Undo, counts as an edit that Undo keeps, and in a field that inherits from the origin it is saved: Save used to leave out such a correction, a switched toggle or a changed heading level, and the field went back to inheriting. A correction typed right after Save counts as an edit that a translation leaves alone, and after Undo the form stays unsaved while it holds such a change, so leaving the page asks first.
- Text moved within a field counts as an edit, so a translation leaves it alone and Undo keeps it: to another row, cell or field of a set, or into a new Bard paragraph by pressing Enter mid-sentence. So does linking a word, making it bold, moving formatting or changing a link title in a Bard field.
- A Markdown or code field whose stored text has Windows line breaks no longer reads as edited in the form: Translate skipped such a field that inherits from the origin, and Undo reported a fill of it as kept and left it localized.
- A translation whose origin someone else saves while the model works is no longer saved with the translation of the text from before: the editor stops with "The origin was changed while it was being translated. Start again.", and Translate into… translates the new text. When the localization, its origin or the term is deleted or detached meanwhile, the editor says that it no longer exists, instead of showing a server error.
- Translate, Review, Retry and Undo do not start while Statamic saves the form ("The form is being saved. Try again when the save has finished."). Before, the save's response replaced a fill that then stayed localized, so the next save stored the text from before as the localization's own. With Statamic's autosave on, the message that refuses a save during a translation appears once per translation instead of at every autosave.
- A translation still running when its form closes, or when another form opens in its place (a create page, a global set, a user or preferences page), is stopped. Before, it kept sending requests, and the new form refused every save, with no Cancel to press, until the page was reloaded.
- On a published entry in a collection with revisions, the origin's banner says "Publish first: the translations are made from the published entry.", because Save puts the changes in the working copy, which is not what is translated; it used to say "Save first". After Publish, the banner reads the statuses again, so it offers to update the localizations the published changes made outdated without a reload. Publish during a translation stops it and puts back the fields it filled, which the next save used to store with the published text as the localization's own and record as translated.
- Translate no longer fills a field that a condition hides, and a filled field that a condition hid before Save is left out of the save: Statamic stored such a field empty, without a warning. The banner lists it to translate. A filled field put back to inheriting with Statamic's sync button before Save is no longer reported as not saved because it was hidden.
- After a translation that finished with fields it could not translate, such as when the provider stayed down, the banner offers **Retry** and says so on the line that names them. It used to say "No fields were translated." with no way to try again.
- Text typed into the Model or Reviewer box of the editor's options to search the list is no longer taken as the model when the box loses focus or on Enter. Translate used to send the search text as the model, and the options remembered it.
- The editor's plans, which hold the text being translated and the model's answers, are deleted from the cache once the form is saved with their translation. The privacy page now says that other plans stay for `plan_ttl`, and on a `file` or `database` cache until it is cleared.
- A run translates a localization translated from another one that the run updates (German from Greek, say), and a navigation whose pages link entries the run creates. Their estimate found nothing to do yet, and the run skipped them; `tolk:translate --dry-run` now says "nothing to do yet" for them.
- A review with **Overwrite manual edits** keeps a field someone edited while its requests ran. It used to write the text it reviewed back over the edit.
- A review of existing translations that could not run, because the reviewer stayed unavailable or its requests were refused, cut off or rejected, ends with errors, and `tolk:translate --mode=review` exits with 1. It used to read "reviewed, nothing to correct", with a completed run and exit code 0. A field that got corrections while another part of it could not be reviewed is listed as partly reviewed.
- A refused request is split until the refused text is alone, so one refusal in a large batch leaves only that text untranslated. Before, up to an eighth of the batch, parts of other fields included, failed as refused.
- When the cache is cleared during a run (a deploy's `php artisan cache:clear`, say), an item whose plan is lost is planned again at once. A worker used to repeat the requests whose answers were lost and then translate the whole item once more, paying for both.
- An item whose process dies while working on it (memory exhausted, a job's timeout) fails after three attempts. A queue lane or the run page used to take it back again and again without counting an attempt, so the run never ended.
- A command-line run resumed or retried on its run page, which hands it to the browser or a queue, sends requests of the web size with the web timeout, splitting the larger ones the command planned without a call. It used to send requests of 10,000 characters with the 180-second timeout from the browser.
- Creating a run over a whole collection or site, and the estimate that `tolk:translate` and `tolk:site` make next, fit a 128M memory limit: they no longer hold every entry in memory, which on a few hundred long articles ended in "Allowed memory size exhausted" without a run.
- A run into a published localization whose working copy was restored from an unpublished revision (its "unpublish" or creation revision) saves into the working copy. It used to save straight to the entry, which took the live page offline, and translated it again on every run.
- A run item retried after a save that threw (in a site's own `EntrySaved` listener, say) ends done, and a localization the first attempt created is finished as a new one. The item used to end skipped as edited by someone, and such a localization could stay a draft although the run was to publish it like its origin.
- The run page drives or follows a run it finds started, resumed or taken over elsewhere, instead of showing it running without moving it. Opening the page of a run the editor's push follows no longer starts a second driver, which took the first one's claims and lost the items' waits, attempts and usage. Leaving a page that drives a browser run through a Control Panel link or Back asks first, as closing the tab does; it used to pause the run without a word.
- The origin's banner says when a translation pushed to the queue has stopped moving, and its creator can move it to the page with **Translate in this page instead**, with **Translate content** alone. Before, a site whose queue worker was not running showed the translation running at 0% forever.
- A run started before its estimate finished says how many items the estimate covers, instead of "Estimating…" until its end.
- A filtered list of a run's items that shrank below the page shown goes to its last page, instead of reading "No items." without a pager.
- The run page and the command line say in words why a part of a field failed ("the model kept breaking its formatting", "the provider rejected the request"), and the run page lists apart a field that strict mode left unsaved, instead of "Not changed: body (invalid)".
- **Try again** after a failed **Count again** on the Overview counts afresh, instead of showing the counts from before **Count again** as finished.
- A queue worker reads roles, groups and permissions again before each job, so a site access or permission taken away in the Control Panel applies to that user's next queue run at once, instead of once the worker restarts.
- A queue worker that cannot find a run's log, such as a worker on another server without the `runs.path` folder, logs a warning naming `runs.path`; the run used to read "This run is not moving" without a word. The installation guide says what a site on several servers must share besides the cache store.
- When `tolk:translate` dies without unwinding (a fatal error, or a signal sent to the command alone), its run is cancelled and its workers stop, instead of translating every remaining item with nobody to save them. `tolk:doctor` warns when the command line's PHP lacks the `pcntl` extension, without which Ctrl-C ends `tolk:translate` and its workers at once, when it lacks `posix`, and when php.ini disables `pcntl_signal`, where the commands used to fail right after creating the run.
- `tolk:site --dry-run` warns about the collections it would enable whose route is set per site but not for the new site, as the run does.
- With Statamic's git integration on, `tolk:lang`, `tolk:forms`, `tolk:doctor` and the Audit page warn while `statamic.git.paths` leaves out `lang/`: the commit held the translation state but not the translation files.
- When Statamic's Eloquent driver keeps the content in the database, the Audit page and `tolk:doctor` warn while the state files sit in the site's folder, and the docs say to set `state.path` to a folder that every deploy keeps and to back it up with the database. A deploy that replaced the site's folder, such as one to a new release folder, took the state with it, so every translation read as edited by hand.
- A state file that does not parse, such as one a git merge left conflict markers in, fails only its own item, with an error that names the file, and `tolk:doctor` and `tolk:prune` list it. It used to break the banners, the Overview, `tolk:status`, runs and deleting the content.
- A wrong or revoked Gemini key, which Google answers with HTTP 400, and a Gemini project without billing or in an unsupported region stop a run with Google's message. They used to count as a refusal of one request, so a run ended completed and saved each field's source-language text over its translation, or with Gemini as the reviewer saved the translations unreviewed. A used-up daily or zero Gemini quota also stops a run at once, instead of being retried as a short rate limit, and another Gemini rate limit waits as long as Google asks.
- On a Redis cache, a rate limit or an overload pauses the provider for every process. The pause was read back as none, so runs kept calling a provider that had asked them to wait, and a paused fallback provider still got requests.
- With laravel/ai 1.2.1, which a fresh install gets, each request is one provider call again: the SDK no longer waits out a short Retry-After of a rate limit or an overload and calls again inside Tolk's call, which doubled the calls and held a web request for up to ten seconds more.
- On laravel/ai before 1.2.1, an OpenAI answer stopped by its content filter fails as refused after one call, instead of being sent again with a doubled output limit and failing as too long.
- A translation that another save overtook, in a form left open while a run, an automatic update or a second tab saved the same field, reads outdated when the form is saved later with the text untouched. It read edited by hand, so no Update refreshed it.
- When Update removes a translation because the origin's field was emptied, the field keeps its history, so a stale form or a restored revision that puts the text back reads outdated and the next Update removes it again. It read edited by hand.
- **Protect this entry from updates** records an outdated machine translation against the origin it was translated from, so it needs attention afterwards, and leaves out a field with a part left untranslated, so Update still completes it. It recorded both as checked against the current origin.
- Fields left empty in a term created with another site selected inherit from the origin, and a localization's Bard field that the Control Panel saves as a copy of the origin's Bard without text (only an image or a rule) is recorded as such a copy, so neither reads as emptied by hand: both are translated once the origin has text.
- The localizations that Statamic's **Duplicate** action creates keep the translation state of those they were copied from, so their translations stay tracked and Update translates them once the copy's origin is rewritten. They read edited by hand (untracked).
- Changing a term's slug in the taxonomy's default site moves its translation state to the new slug, so its translations stay tracked instead of reading edited by hand (untracked).
- `tolk:prune` keeps the state of entries in a site their collection no longer lists, also once the Stache is rebuilt, so their translations are tracked again when the site comes back; it adds the collection and site to state written by 1.0.0-beta.1 whenever it finds the entry. The editor no longer answers such a localization with a server error.
- Translations made with `--from` from a site other than the default keep their source: a navigation translated that way reads current on the Overview and in `tolk:status`, Update and `tolk:baseline` keep that site as its source, and a navigation whose only tree is in that site gets its row. `tolk:prune` keeps the state of translation files, form texts and navigations translated with `--from`, and of a navigation in a site taken out of the configuration, as it does for terms and global sets.
- A navigation set to expect a root page keeps its root as a text-only page in a site where the root's entry has no localization yet, and Tolk checks a tree before it saves it. The next page used to take the root's place, and with children of its own it made a tree Statamic cannot read, so every page that renders the navigation failed.
- A Bard code block or line break stored in the format of Statamic's older Bard editor (`code_block`, `hard_break`, in an entry not saved since) is read as Statamic reads it: the code is left alone instead of translated, and the line break reaches the model as a line break.
- `tolk:forms` leaves out a form's title, label, placeholder or email subject that is a key of a source-language PHP translation file or of a package (`forms.contact.name`), and lists the entries an earlier run wrote for them. Such an entry in `lang/{lang}.json` hid the key's own translation, so the form and its emails showed the key, or a translation of the key, instead.
- `tolk:lang` leaves out a key that only the target PHP file has where the source nests its keys differently (a `password` string where the source has `password.letters`), names it in the result, and refuses a write that would not hold every translated key. It used to lose the new translations, report the file done, and pay for them again on every run.
- On a host whose `opcache.restrict_api` leaves the script out, `tolk:lang` and `tolk:forms` no longer report a file they wrote as not written, which kept them from recording its translations.
- `tolk:lang` rejects a translation of one plural form that holds a `|`, which added a form and shifted the ones after it. It no longer presents a string whose `|` is text (`Blog | :site`) to the model as plural forms, and its note for languages with more plural forms says to leave such a string as it is instead of adding forms to it. `tolk:forms` translates form texts whole, since Statamic picks no plural form for them.
- A free-text setting that Statamic cannot read as Antlers, such as `Keep {{ and }} unchanged.`, is refused with a hint to put it between `{{ noparse }}` and `{{ /noparse }}`, which Tolk leaves out of the prompts. Saving it used to fail with a server error, and in a settings file edited by hand it broke every read of the settings with an error that named neither the file nor the cause. A glossary term and the same term between noparse tags count as one term, and `tolk:profile --save` saves a profile that holds `{{` between noparse tags, or with each `{{` written as `{ {` where the tags would not keep it as written (an end tag in capitals, a final `{`), instead of stopping with Statamic's syntax error after the provider call.
- The term listing's **Translate…** is offered to a translator who may edit the selected terms in any site of the taxonomy. It was hidden from, and refused to, a translator without access to the taxonomy's first site.
- The description of **Run bulk translations** in the role editor names the Audit page, which the permission also opens, and the **Tools › Translations** menu.
- The extension guide and the Boost guideline call `Tolk::registerFieldtype()` from `AppServiceProvider::boot()` inside `Statamic::booted()`. Called directly, as they showed before, it gave a fieldtype of an addon that boots after Tolk the handler but not the **Translate automatically** and **Translation hint** options.
- The Boost guideline names Tolk's own `TOLK_ANTHROPIC_API_KEY`, `TOLK_OPENAI_API_KEY` and `TOLK_GEMINI_API_KEY`, which Tolk reads before the AI SDK's variables, and `tolk:doctor` and the Audit page name the config each key comes from. An agent asked to change Tolk's key changed the SDK's instead.
